Split “Semantic Mesh” into two pages: Ontology and Ask AI

Today one screen holds four separate products: a glossary, a graph, an NL-to-SQL studio and a governance toolkit. Each is aimed at a different person doing a different job. The proposal is to give the AI studio its own page, fold governance into the place where people actually change metrics, and open the Ontology page with a short overview that says what each part is for.

Page 1OntologyFor data stewards and modelers. Overview, Domains, Map, Health.
Page 2Ask AIFor analysts and business users. Ask a question, get a governed answer, see how it was built.
GovernanceMoves into context“What breaks if I change this?” lives on the metric itself. A Health tab rolls up every check.

  1. Internal name as the page title. “Semantic Mesh v2.4” tells a new user nothing about what they can do here.
  2. Tab labels are sentences. Two tabs are 5 to 6 words with ampersands, so the header overflows on laptops and the tabs scroll sideways.
  3. The header carries everything: brand, four tabs, a telemetry strip, two primary actions and refresh, all at the same visual weight.
  4. Three panes plus a second tab row on the Domains view. The metrics table has 6 columns, and SQL formulas push it wide.
  5. The inspector is always open, so it takes 340px even when nothing is selected.
  6. The AI studio is a workbench, not a flow. Engine choice, trace, SQL, certification and results all appear at once, before anyone has asked a question.
  7. Governance is four empty forms. Users must type a metric name, a change type and a DAX expression to see anything, and nothing explains when you would want to.
  8. No “why”. No view explains what a feature is for or what to do first, so the value of the ontology stays hidden.
Proposed structure

Two sidebar entries, short tab names

Split by who is using it and what they came to do. Stewards curate definitions, and analysts consume them. Governance checks act on definitions, so they stay with the Ontology page but get triggered from the metric being changed.

Build order

How to get there without a rewrite

Most of the existing panels can be reused. The work is mainly moving them and splitting the 2,800-line component.

  1. Split the component. Break OntologyDomainManager.jsx into DomainsView, HealthView and AskAiPage, with domain data moved into a shared hook (useOntologyDomains).
  2. Add the /ask route and sidebar entry. Redirect /ontology?tab=ai to /ask so existing links keep working.
  3. Rename tabs and slim the header to a title, a subtitle and two actions. This alone fixes most of the overflow.
  4. Turn the inspector into a drawer that opens on row click, and add the Impact / Parity / Lint quick actions for the selected metric.
  5. Rebuild Health as a results list, reusing the existing blast-radius, parity, lint and RLS panels as the expanded detail of each row.
  6. Add the Overview tab last, including the empty-state setup steps for projects with no domains.
