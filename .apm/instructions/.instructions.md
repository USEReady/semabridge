# SemaBridge Architecture & Coding Standards

## Stack

- **Runtime**: Python 3.10+
- **Database**: DuckDB (embedded OLAP) — NEVER use SQLite
- **ORM Fallback**: SQLAlchemy/SQLModel (optional via `pip install semabridge[orm]`)
- **Validation**: Pydantic v2
- **API**: FastAPI + Uvicorn
- **CLI**: Typer + Rich
- **Auth**: MSAL (Microsoft Entra ID)

## Mandatory Rules

### 1. OSI Intermediate Model First
All conversions: `Source → OSI → Target`. Direct source-to-target conversion is forbidden.
OSI definitions: `src/semabridge/intermediate/models.py`

### 2. DuckDB Only
- Use `duckdb.connect()` for all DB operations
- NEVER use `sqlite3.connect()`
- Use JSON column type for snapshots
- DB abstraction: `src/semabridge/repository/db.py`

### 3. No Inline Secrets
- NEVER accept passwords/tokens as function parameters
- Secret config keys must end with `_env` suffix
- Use `pydantic.SecretStr` for secret fields
- Read credentials from `os.environ` inside methods

### 4. Custom Exceptions Only
Use exceptions from `semabridge.core.exceptions`:
- `ConnectorError`, `ConversionError`, `ValidationError`
- `RepositoryError`, `MigrationError`, `PBIXParsingError`, `RateLimitError`
- NEVER raise bare `Exception`

### 5. Logging Standards
- Use `from semabridge.utils.logger import get_logger`
- Log format includes thread ID and function name automatically
- Credential redaction filter scrubs secrets from all output
- NEVER use `print()` in production code

### 6. Type Safety
- All function signatures must be fully annotated
- Avoid `Any` — use `TypedDict`, `Protocol`, or Pydantic models
- Use `Optional[X]` for nullable types

## File Structure

```
src/semabridge/
├── core/           # Exceptions, Interfaces, Settings
├── connectors/     # Fabric, Snowflake, Local PBIX
├── formats/        # Format definitions, composite models
├── converter/      # TMSL↔OSI transformation
├── intermediate/   # OSI models (Pydantic)
├── repository/     # DuckDB manager, versioning, DB abstraction
├── cli/            # Typer CLI
├── api/            # FastAPI + WebSocket alerts
├── plugins/        # Plugin architecture
└── utils/          # Logging, helpers
```

## Naming Conventions

| Element | Convention | Example |
|---------|-----------|---------|
| Files | `snake_case` | `fabric_connector.py` |
| Classes | `PascalCase` | `FabricExtractor` |
| Variables | `snake_case` | `model_name` |
| Constants | `UPPER_SNAKE_CASE` | `MAX_RETRY_COUNT` |

## Testing
- Run: `pytest tests/ -v`
- Minimum 80% coverage for new code
- Current baseline: 374 tests, all passing
- Mock external APIs — never call real endpoints in tests
